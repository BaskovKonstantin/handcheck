# HandCheck — ТЗ (сжато для реализации)

Источник: ФСП спец. трек 2026, PDF 9 стр. Полный текст у оператора: `OpenBas/context/fsp-spec-track-tz-extract.txt`.

## Смысл продукта (нельзя ломать)

Платформа **не** витрина чужих вакансий и **не** «кандидат откликается вслепую».

1. Кандидат проходит **опрос + тест на заявленный грейд**.
2. Система присваивает **категорию = специализация × грейд**.
3. Работодатель ищет **категорию / банк**, сам шлёт **приглашение с вилкой ЗП**.
4. Контакты кандидата **скрыты**, пока он не принял приглашение (или сам не откликнулся — доп. сценарий).

Ориентир механики: LHH / Hired — инициатива у работодателя. Это **главный критерий жюри (35%)**.

## MVP обязательно

### Кандидат
- Профиль (форма; PDF+OCR — желательно позже)
- Опрос отрасли/специализации → выбор грейда → тест → категория
- Статус категории/грейда, история теста, пересдача выше/ниже с **лимитом частоты** (по умолчанию 90 дней)
- Входящие приглашения: принять / отклонить + статусы
- Приватность, согласие на данные, опциональная связь с **FSP ID**
- Видит только свои данные

### Работодатель
- Профиль компании
- Описание потребности → подборка категорий/кандидатов **с обоснованием**
- Поиск по банку: специализация, грейд, категория, стек, наличие ФСП
- Приглашение с оффером и ЗП **от–до ₽** без обязательной вакансии
- Статусы приглашений
- Контакты кандидата не видны до accept

### Правила подбора
- Выдача по **категории теста**, не по самоописанному резюме
- Ранжирование внутри категории: результат теста + буст ФСП (если есть)
- Фильтры не должны «съедать» уже полученную подборку
- ЗП «от–до» обязательна в приглашении (и в вакансии, если вакансии есть)

### Регистрация
- Email + подтверждение
- Верификация компании и модерация вакансий в MVP **не нужны**

## Тест и грейд (критерий 25%)

- Один общий набор заданий на всех — **плохо** (утечка)
- Уникальная LLM-генерация на каждого — **риск несравнимости**
- Нужен **свой устойчивый подход** (см. `docs/ARCHITECTURE.md` → Assessment)
- Грейд **не режется принудительно** вниз: можно пересдать ниже/выше
- Лимит смены грейда: конфиг `GRADE_COOLDOWN_DAYS` (default 90)

## Желательно, не блокер MVP
- Публикация вакансий + отклик кандидата
- Короткие регулярные задания от работодателя
- PDF резюме → разбор

## За рамками кода, нужна концепция в доке
- Антифрод вакансий / недобросовестные работодатели
- ATS-интеграции
- Реальная интеграция с реестром ФСП (API не выдают; обязателен кейс «нет истории ФСП»)

## Критерии жюри
| Блок | Вес | Что закрывает в коде |
|------|-----|----------------------|
| Механика подбора | 35% | need → match → invite → accept/reveal |
| Тест / валидация / категории | 25% | survey + forms + score + category |
| UI | 10% | два кабинета + демо-сценарий |
| Техника | 7% | Docker, OpenAPI, безопасные секреты |
| Полнота + доки | 6% | README, ARCHITECTURE, валидация |
| Доп. функционал | 7% | вакансии / PDF / short tasks |
| Питч | 10% | только финал |

## Демо-сценарий (обязателен)
Регистрация → опрос/тест → категория → поиск работодателя → приглашение (+ отклик, если сделан). Отдельно объяснить тест и подбор.
