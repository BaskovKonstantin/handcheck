# Jury demo — HandCheck (FSP / ЛЦТ)

Короткий сценарий для оценки MVP без доступа к продакшен-данным.

## Окружение для оценки

- **RAM:** ~32–64 GB  
- **CPU:** 4–16 vCPU  
- **GPU:** не требуется (0 GPUs) — весь стек Node.js + SQLite + ffmpeg для записей звонков  
- Локально: `npm start` или `docker compose up` (см. комментарии в `docker-compose.yml`)

## Click-path (≈10 минут)

1. **Работодатель** — вход `cafe@demo.local` → `/employer/deck`.  
   - Листайте колоду: сверху кандидаты с подтверждённой категорией и выше rank (Анна с domain boost обычно выше demo3–8).  
   - Внизу — **«Backend × Middle — неподтверждён»** (`demo-unconf@demo.local`): профиль не скрыт, но ниже в ранжировании.  
   - Пилюля «неподтверждён» — пунктирная, приглушённая.

2. **Список совпадений** — `/employer/list` для той же потребности: те же метки `categoryStatus` / подпись категории.

3. **Кандидат без категории** — `demo-unconf@demo.local` → `/candidate/today`: статус неподтверждён, CTA «Пройти тест».

4. **Кандидат с категорией** — `anna@demo.local` → «Сегодня»: подтверждённая категория, приглашения.

5. **Регистрация и 152-ФЗ** — `/auth?mode=register`: дата рождения, согласие (чекбокс не предзаполнен), для 15–17 — согласие представителя; `/privacy` с оператором по умолчанию.

6. **Тест** — `anna` или новый кандидат → `/candidate/tasks`: короткие вопросы **60 с по серверному дедлайну** (после перезагрузки таймер = остаток с сервера). Cooldown пересдачи **30 дней** (`GRADE_COOLDOWN_DAYS`).

## Что проверить в ранжировании

- Подтверждённые (`categoryStatus: confirmed`) всегда выше неподтверждённых при прочих равных.  
- Среди подтверждённых: выше `test_score` + `domain_boost` (опыт в домене потребности) + FSP.  
- Провал теста **не снимает** уже подтверждённую категорию (повторная батарея → cooldown, старая категория в API кандидата).  
- Контакты в колоде скрыты до accept приглашения (`validate-privacy`).

## API (для жюри-технарей)

- `GET /api/candidate/category` → `status`: `confirmed` | `unconfirmed`  
- `GET /api/employer/needs/{id}/deck/next` → `card.categoryStatus`, `card.categoryLabel`  
- Список матчей — те же поля в элементах.
